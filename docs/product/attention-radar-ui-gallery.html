z-Bot / design system proposal

Attention Radar, across the board.

Mission Control's dark operational calm becomes a shared workbench language—without making every route look or behave like a dashboard.

How to read this
Each frame is a canonical route, not a new feature. Colored signals describe state, panels own their own scroll, and the central canvas always serves the page's primary job.
One focus, not more noise

The dominant center panel is where work happens. Supporting context stays in rails and inspectors.

Signal has meaning

Cyan = current/live; green = healthy; amber = attention; red = failed. Every status is named.

Dense, never cramped

Hairline borders, compact operational type, and one limited focus wash replace generic card grids.

Each pane owns its scroll

Desktop workbenches have bounded scroll areas. Tablet and phone collapse to a deliberate single column.

Plug-and-play semantic memory

The z-Bot sidecar must depend on a narrow semantic capability contract, not a storage implementation. Engram owns persistence, retrieval, graph, taxonomy, and ontology.

Boundary

Conversation messages and execution checkpoints remain local runtime data. Recall returns evidence with provenance, ranking rationale, and bounded content.

recall(query, scope, policy) → EvidencePacket[]

Operational consequence

Changing Engram from SQLite to Postgres or Surreal does not change the z-Bot sidecar.
